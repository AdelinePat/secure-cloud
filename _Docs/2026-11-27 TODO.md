# 2026-11-27 TODO

## Still needed for an MVP

1. User registration. Auth only has /auth/login and /auth/refresh, and the client only has a loginscreen. The only accounts are alice_test and bob_test from the seed script, so a demo can't go beyond those two. You need POST /users in auth, a route for it in the gateway, and a sign-up form in the client.
2. Messaging handles one request at a time. messaging/src/main.cpp:148 still waits for a connection, handles it, and only then accepts the next one, all on a single shared DB connection. Every client polls history on a timer, so a few clients already queue up behind each other. Moving it to the async Beast pattern that gateway and file already use fixes this, and it would also split up that 641-line main.cpp.
3. TLS between client and gateway. The client connects to http://localhost:8080 (client/src/main.cpp:19), and the gateway only speaks plain HTTP. The services do use mTLS when they talk to audit, and the gateway certs exist, but nothing loads them on the public side.
4. Group chats aren't end-to-end encrypted. GET /conversations/{id}/peer-key returns TWO_PARTICIPANTS_REQUIRED for anything other than a two-person chat (messaging/src/main.cpp:233). That's fine if the demo sticks to 1:1 chats. If it needs groups, the plan is one random key per conversation, with a copy encrypted for each member's public key.

Can wait until after the MVP

- Missing auth endpoints: the spec lists /auth/revoke, /auth/validate and /auth/permissions, and there's no logout. The revoked_at column exists, but nothing sets it.
- Gateway JWT check: the gateway doesn't verify tokens itself, so each service has to.
- History: it's fixed at 50 messages (messaging/src/main.cpp:591) with no paging.
- Real-time updates: there are no WebSockets, so the client polls.
- Table ownership: messaging writes identity keys straight into auth's users table.

One thing to fix before showing anyone

The private keys in certs/, including certs/ca/ca.key, are committed to git. That's acceptable for a school demo, but anyone who has the repo can sign certificates your services will trust. Generate them at startup the way tools/ensure-jwt-keys.sh already does for the JWT keys, and add certs/ to .gitignore.
